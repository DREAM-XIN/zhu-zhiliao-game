# F-ZHIZHILIAO-AUDIO-0003 — 游戏音效与声音开关 Requirement

## 1. 背景

当前“竹知了”网页小游戏已经具备 30 秒回合、有效摇动计分、Combo、随机 modifier、倒计时显示和结算体验，但用户在线体验后明确反馈“没有声音”。本 Feature 为现有玩法增加轻量、即时、可关闭的声音反馈，同时保持移动端优先、快速加载、无障碍和现有玩法语义不变。

## 2. 目标

1. 在用户首次明确交互后，为关键游戏事件提供轻量且可区分的声音反馈。
2. 遵守浏览器 autoplay 限制：页面加载后、用户尚未产生明确交互前，不得主动播放声音。
3. 提供清晰可见、可理解、可即时切换的声音开/关控制。
4. 音频能力不可用、初始化失败或恢复失败时，游戏仍须完整可玩，不影响计分、时序、输入或结算。
5. 不改变当前 30 秒回合、有效 shake 判定、Combo、modifier、计分和结果语义。

## 3. 用户体验需求

### 3.1 音频激活与 autoplay

- 页面首次加载时不得自动播放任何游戏声音。
- 声音系统只能在用户产生明确交互后尝试初始化或恢复，例如点击“开始游戏”、操作声音开关，或首次有效游戏交互。
- 浏览器拒绝、延迟或不支持音频初始化/恢复时，不得产生阻塞游戏的未处理错误，也不得要求用户完成额外步骤后才能游玩。
- 当声音设置为“开”且音频能力可用时，首次有效用户交互之后的关键事件应能获得声音反馈。

### 3.2 必须覆盖的声音反馈

以下事件必须具有声音反馈，且不同类别之间应能被用户合理区分：

1. **有效拖拽 / 摇动反馈**
   - 仅针对已经被现有输入/摇动判定逻辑认可的有效动作提供反馈，不要求也不允许对每个原始 `pointermove` 无节制播放。
   - 高频连续操作必须采用节流、聚合、最小触发间隔或等价策略限制播放密度，避免刺耳的声音洪泛、明显重叠失真或不必要的性能开销。
   - 声音节流不得反向影响有效 shake 的判定、计分或 Combo 计算；声音可以少播，但游戏事件不能因此少算或改变。

2. **Combo / 连击反馈**
   - 连击形成或提升时应提供可感知的 Combo 声音特征。
   - Combo 声音可以与有效 shake 反馈协同设计，但用户应能够通过音色、音高、节奏或其他轻量方式感受到连击增强，而不是完全无法区分的重复单音。
   - 高频 Combo 仍受声音密度控制约束。

3. **Modifier 触发反馈**
   - 当 modifier 从未激活状态进入激活状态时应提供明确反馈。
   - 不应因为 modifier 持续处于激活状态而在每一帧或每次状态读取时重复触发同一提示音。

4. **最后 3 秒倒计时提示**
   - 一局最后 3 秒应提供 3、2、1 的倒计时声音提示。
   - 每个秒值至多触发一次对应提示，避免由于渲染帧或重复状态计算造成重复播放。
   - 倒计时声音不能替代现有可视时间显示。

5. **一局结束 / 结算反馈**
   - 回合从 playing 进入 finished / 结算状态时应提供一次结束反馈。
   - 结算音效不得改变结果计算、结果标题、最高 Combo 或分数。

### 3.3 声音开关

- 页面应提供明确可见的声音开/关控制，移动端和桌面端均可操作。
- 控件必须通过可见文本、图标加文字、ARIA 状态或等价方式表达当前“声音开启 / 声音关闭”状态；不能只通过是否听见声音来表达状态。
- 用户关闭声音后应即时静音，后续游戏事件不得继续产生可听声音。
- 用户重新开启声音后，在浏览器允许且音频能力可用的前提下，后续关键事件应恢复声音反馈；恢复失败不得影响游戏。
- 声音开关不得与 `prefers-reduced-motion` 绑定。减少动画与是否播放声音是两个独立维度。

### 3.4 本地持久化决策

本 Feature **要求本地持久化声音偏好**：

- 声音开/关偏好应保存在浏览器本地存储中，仅用于当前游戏客户端，不需要后端服务。
- 没有历史偏好时，默认状态为“声音开启”，但默认开启不代表允许自动播放；仍必须等待首次明确用户交互后才能实际发声。
- 用户选择静音后，刷新页面或再次访问时应保持静音偏好。
- 用户重新开启声音后，该偏好也应被持久化。
- 本地存储读取或写入失败时，应安全降级，不得阻塞游戏；至少保证当前会话仍可切换声音状态。

## 4. 无障碍与降级要求

- 声音不得成为任何游戏状态的唯一提示。
- 静音、系统音量为零、浏览器不支持音频或 AudioContext 不可用时，用户仍应能够依靠现有视觉/文本信息完整开始、游玩并完成一局。
- 现有时间、分数、Combo、modifier 和结算信息应继续以可视方式表达。
- AudioContext 创建、初始化、`resume`、播放或清理失败均应被安全处理，不得抛出导致游戏流程中断的错误。
- 移动端触摸输入、桌面端鼠标/触控笔输入均需考虑；声音功能不得破坏现有 pointer capture、拖动位置或有效 shake 检测。
- 现有 `prefers-reduced-motion` 行为必须保持；声音开关与 reduced-motion 独立，不因用户减少动画而自动静音，也不因声音开关而修改动画偏好。

## 5. 技术与产品约束

- 优先采用浏览器原生轻量音频能力（例如 Web Audio API）生成程序化音效。
- 不引入大体积 MP3、音乐包或其他明显增加首屏/游戏加载成本的音频资源。
- 不新增后端服务或远程音频依赖。
- 具体 oscillator、envelope、频率、波形、节点结构、音量曲线等实现细节由 Design 阶段决定，本 Requirement 不预设。
- 音效系统应作为现有游戏状态/事件的旁路反馈层，不应成为计分、Combo、modifier、计时或结算逻辑的权威来源。

## 6. 兼容现有玩法的硬性约束

以下现有语义不得因本 Feature 改变：

- 单局时长保持 30 秒。
- 有效 shake 的检测规则保持现有语义；声音节流不能改变 shake 事件本身。
- 分数计算保持现有语义。
- Combo 的形成、窗口、清零和最佳 Combo 记录保持现有语义。
- modifier 的触发概率、激活时长和倍率语义保持现有语义。
- 回合结束与结算状态转换保持现有语义。
- 现有移动端优先布局、可视状态提示、ARIA/可访问性和 reduced-motion 能力不得回归。

## 7. Out of Scope

本 Feature 明确不包含：

- BGM / 背景音乐。
- 大体积音乐或音效资源包。
- 用户上传、自定义或录制音频。
- 后端音频服务、音频 CDN 或服务端声音配置。
- 核心计分规则修改。
- 回合时长修改。
- Combo / modifier 玩法规则修改。
- 新玩法系统、新道具系统或新关卡系统。
- 音量混音器、独立的多轨音量设置或高级音频设置页面。

## 8. 验收标准

### AC-01 首次交互前不自动播放

- Given 用户首次打开页面且尚未进行任何明确交互
- When 页面加载、渲染并停留
- Then 不得自动播放游戏声音，也不得因 AudioContext autoplay 限制产生影响游戏的错误。

### AC-02 首次有效交互后可发声

- Given 声音设置为开启且浏览器支持所需音频能力
- When 用户完成首次明确交互并随后触发有效游戏事件
- Then 关键事件能够产生对应声音反馈。

### AC-03 静音即时生效

- Given 当前声音开启
- When 用户切换为“声音关闭”
- Then 控件立即显示关闭状态，后续游戏事件不再产生可听声音，且游戏输入、计分与计时继续正常。

### AC-04 重新开启可恢复

- Given 用户此前已静音
- When 用户切换回“声音开启”并产生后续关键游戏事件
- Then 在浏览器允许音频的前提下声音恢复；若恢复失败，游戏仍正常运行。

### AC-05 高频拖动无声音洪泛

- Given 用户持续快速来回拖动竹知了
- When 产生大量 `pointermove` 和连续有效 shake
- Then 声音反馈具有明确的播放密度控制，不会为每个原始 `pointermove` 无限制播放，不出现不可控的声音洪泛；同时有效 shake、计分和 Combo 仍按原逻辑处理。

### AC-06 关键声音可区分

- Given 声音开启并完成一局游戏
- When 分别触发有效 shake/Combo、modifier、最后 3 秒倒计时和回合结算
- Then 用户能感知这些关键类别具有可区分的声音反馈；modifier 不因持续激活而重复洪泛，3/2/1 每秒至多提示一次，结算仅在结束转换时触发。

### AC-07 音频不可用时安全降级

- Given AudioContext 创建/恢复失败、浏览器不支持音频或播放过程中出现异常
- When 用户开始并完成一局
- Then 不出现阻断游戏的未处理错误，用户仍可正常拖动、计分、形成 Combo、触发 modifier、看到倒计时并进入结算。

### AC-08 声音状态可理解且可持久化

- Given 用户查看声音控制
- Then 无需依靠听觉即可知道当前开启/关闭状态。
- When 用户切换声音状态并刷新或重新访问页面
- Then 在本地存储可用时保持上次选择；本地存储不可用时安全降级，不阻断当前会话。

### AC-09 reduced-motion 独立

- Given 用户系统启用了 `prefers-reduced-motion`
- When 用户进入游戏并单独操作声音开关
- Then reduced-motion 行为保持现状，声音仍由声音设置独立控制，两者互不隐式修改。

### AC-10 现有游戏语义无回归

- 验证单局仍为 30 秒。
- 验证现有有效 shake 判定和计分结果不因声音播放/节流改变。
- 验证 Combo、best Combo、modifier 和结果计算语义不变。
- 验证静音环境仍可完整游玩。

### AC-11 工程检查

以下命令必须通过：

- `npm run typecheck`
- `npm run test`
- `npm run build`

### AC-12 GitHub Pages 在线验证

- Feature 进入后续发布流程并部署到 GitHub Pages 后，应在生产地址 `https://dream-xin.github.io/zhu-zhiliao-game/` 实机验证至少：首次交互前无自动播放、声音开关即时生效/恢复、关键音效存在、高频拖动无洪泛、静音下完整可玩。
- 在线音频不可用或被浏览器策略限制时，页面仍应保持可玩并无阻断错误。
